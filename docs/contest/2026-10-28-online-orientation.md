## 1. 공모전 안내

### 개요

- 운전자와 탑승자를 위한 차량용 앱을 만들어 출품하는 **개발** 공모전입니다. 앱이 완성되지 않았어도 **기획서만으로 지원**할 수 있습니다.
- 접수 기간: **2026.10.21 ~ 11.15**
- 참가 단위: 개인 또는 최대 5인 팀
- 공식 홈페이지: appdevchallenge.auto-hmg.io (접수 양식과 최신 공지)
- 아이디어 흐름: 운전자·동승자 관점의 문제 → 차량 특화 아이디어 → 앱의 사용 경험
  1. **사람에서 출발:** 다양한 취향과 라이프스타일, 운전자·동승자가 원하는 새로운 경험
  2. **차량 맥락으로 구체화:** 디스플레이·오디오 등 하드웨어와 차량 상태·이동 맥락의 결합
  3. **앱의 경험으로 구현:** 제공되는 SDK·API로 아이디어를 구현

### 참가 대상과 공모 분야

- **대학생 부문:** 팀원 전원이 대학(원)생. **일반 부문:** 그 외 모두(일반 개발자, 스타트업 포함)
- 공모 분야 제한 없음. 예: 모빌리티·라이프, 엔터테인먼트, 안전·동승자 케어 등 차량 이동·이용 중의 모든 순간

## 2. 공모전 Q&A

**FAQ (슬라이드)**
- **대학생과 일반인이 섞인 팀은?** 일반인이 한 명이라도 있으면 대표자 신분과 관계없이 **일반 부문**입니다. 경험 차이를 고려한 공정성 때문에 부문을 나눴습니다.
- **여러 작품을 낼 수 있나요?** 네, 개수 제한이 없습니다. 같은 작품의 수정 제출과는 구분해 주세요.
- **외국인, 고등학생·미성년자 참가는?** 조건을 따로 확인해야 합니다. 사무국이 개별 문의를 확인한 뒤 참가 가능 여부와 절차를 공지사항으로 안내합니다.

**라이브 채팅 답변 (현대자동차 담당자)**
- **생성형 AI 사용:** 기획서 작성과 개발 전 과정에서 AI 보조 도구를 쓸 수 있습니다. 단, 참가자가 전체 구조와 로직을 완전히 이해하고 **2차 PT 기술 Q&A에서 직접 설명**할 수 있어야 합니다.
- **기획서 수 제한:** 없습니다. 접수양식이 곧 기획서이고, 중복 출품도 됩니다. 앱 이름(프로젝트명)으로 구분합니다.
- **2차 PT에서 실차 시연:** **지원하지 않습니다.** 앱 검증은 Pleos Playground가 제공하는 **에뮬레이터**로 합니다.
- **현대자동차그룹 임직원·그룹사:** 참가는 가능하지만 시상과 상금 대상에서는 빠집니다.
- **대학생이면서 스타트업을 하는 경우:** 대학생 부문으로 지원합니다.
- 그 밖의 운영 문의는 홈페이지 이메일로 받고 순서대로 답합니다.

## 3. 개발착수 안내 (포티투닷 담당자)

### Pleos Playground

- 현대자동차그룹 SDV 플랫폼 Pleos의 개발자 포털입니다(pleos.ai/playground). 메뉴는 Discover, Docs, Publish, Workspace입니다.
- 플랫폼 소개, 개발 가이드, SDK·API 문서, 테스트 도구, 앱 등록 정보를 한곳에서 제공합니다. 시작 → 환경 구성 → 디자인 → 구현 → 테스트의 전체 과정을 안내합니다.

### Discover: 플랫폼 이해

- **Pleos Connect:** 현대·기아·제네시스 차량용 차세대 인포테인먼트 플랫폼입니다. **AAOS(Android Automotive OS) 기반**이라 안드로이드 앱 개발 경험을 그대로 쓸 수 있습니다.
  - 스마트폰 앱과 다른 점: 주행 중인지 정차 중인지, 차량 상태, 운전자와 동승자 중 누가 쓰는지까지 고려해야 합니다.
- **Pleos App Market:** 차량용 앱 유통 플랫폼입니다. 스마트폰 앱을 차 화면에 옮기는 것을 넘어, **차량이라서 더 유용해지는 앱**을 기대합니다(예: 배터리 상태와 이동 경로를 결합한 서비스, 차 안 상황에 맞춰 동작하는 개인화 서비스).
- **공모전 참가자에게는 현재 공개되지 않은 SDK까지 제공할 예정**이라고 했습니다. 공개 범위에 얽매이지 말고 경험을 구상해 달라는 취지입니다.

### 개발 흐름

기획 → 개발 환경 준비 → UX 설계 → SDK·API로 기능 구현 → 테스트 → 앱 등록

처음부터 모든 기능을 만들기보다 세 질문에 먼저 답해 보라고 권했습니다.
1. 차량 사용자의 어떤 문제를 해결하는가?
2. 그 과정에 어떤 차량 정보나 기능이 필요한가?
3. Playground의 SDK와 개발 환경으로 어떻게 구현하는가?

### Docs: 개발 문서

- 처음이라면 **"Pleos Connect 앱 개발 시작하기(Getting Started)"** 부터 읽습니다. Android Studio 새 프로젝트 생성 → Pleos Connect 에뮬레이터 준비 → Vehicle SDK 연동 → 첫 차량 API 호출 순서입니다.
- Java 또는 Kotlin. 개발 환경 가이드 기준 **최소 Android API 28, Gradle 8.0 이상**. 실제 개발 때는 문서의 SDK 버전과 에뮬레이터 환경을 함께 확인합니다.
- 예제: Vehicle SDK로 도어 상태를 가져와 앱에서 처리하는 흐름. 첫 목표는 차량 API 하나를 정상 호출하는 것으로 잡아도 좋다고 했습니다.
- Workspace에서 개발 과정을 프로젝트 단위로 관리할 수 있습니다.

### Pleos Connect SDK

| SDK | 용도 |
|---|---|
| **Vehicle** | 차량 상태 조회, 제공 범위와 권한에 따라 일부 기능 제어. 도어, 주행 정보, 배터리·충전, 공조 등 도메인 API (예: 배터리 상태로 충전 정보를 주는 EV 앱) |
| **NaviHelper** | Pleos Connect 내비게이션 연동. 목적지 설정, 경유지 관리, 경로 요청, 내비 정보 조회 (예: 여행 장소 추천 → 차량 내비 목적지로 연결). 내비 앱 전체를 새로 만들 필요가 없음 |
| **TextToSpeech** | 텍스트 → 음성 |
| **SpeechToText** | 음성 입력 → 텍스트 |
| **FusedLocation** | 차량 위치 정보 |

- SDK를 많이 쓰는 것이 목적이 아닙니다. 고객 문제 해결에 필요한 SDK를 골라, 그것이 핵심 기능에 어떻게 쓰이는지 분명히 보여 주는 것이 중요합니다.
- 필요한 권한, 호출 방법, 지원 여부는 각 SDK의 프로그래밍 가이드와 API 레퍼런스에서 확인합니다.

**권한**
- **공모전 개발 단계에서는 권한 신청·승인이 필요 없습니다.** SDK 문서가 안내하는 `uses-permission`을 AndroidManifest에 선언하면 Connect SDK를 호출할 수 있고, 그것만으로 에뮬레이터에서 테스트할 수 있습니다.
- 실제로 Pleos App Market에 배포할 때는 심사에서 **승인된 권한만 선언했는지** 확인합니다. 승인되지 않은 권한을 선언하면 심사를 통과하지 못합니다.

### 에뮬레이터와 Virtual Console

- **Pleos Connect 에뮬레이터:** Android Studio에서 차량용 앱을 실행하고 검증하는 가상 환경입니다. 화면 동작과 SDK 연동 기능을 지원 범위 안에서 테스트합니다. 실차 없이 초기 개발과 기능 검증이 됩니다.
- **Pleos Connect Virtual Console:** 차량 상태와 이벤트를 가상으로 설정해 앱 반응을 확인합니다. 예: 기어 변경, 도어 열고 닫기, 배터리 충전 상태 변경. 상태를 바꾸고 → SDK로 받고 → 앱 반응을 검증하는 과정을 반복할 수 있습니다.
- 2차 심사에서 실제 동작하는 앱을 보여야 하므로, 초기부터 에뮬레이터로 구현·테스트하라고 강하게 권했습니다. 설치와 설정은 개발 문서에 단계별로 있습니다.

### 정리 (발표자 요약)

Discover로 플랫폼 이해 → Docs의 Getting Started로 시작 → 아이디어에 필요한 SDK 선택 → 에뮬레이터와 Virtual Console로 핵심 기능 구현·검증.
1차는 기획서만으로도 되지만 개발 산출물을 내면 가산점이 있고, 2차에는 동작하는 앱이 반드시 필요합니다. **차량 환경에서만 줄 수 있는 핵심 가치 하나**를 정하고, 그것을 실제 동작하는 기능으로 보여 주는 데서 시작하라고 권했습니다.

## 4. 기술 Q&A

- **외부 API를 섞어 써도 되나요?** 됩니다. 퍼블릭 네트워크 연결도 가능하다고 보면 됩니다.
- **SDK 사용 승인은?** 개발 단계에서는 별도 승인 없이 공개된 Vehicle, NaviHelper, STT, TTS, FusedLocation SDK를 `uses-permission` 선언만으로 쓸 수 있습니다. 승인은 App Market 배포 심사 때 확인합니다.
- 그 밖의 질문(음성상 "Distraction" 관련으로 들리는 질문 포함)은 상세한 개발 사항이라 나중에 정리해 전달하겠다고 했습니다.
- 개발 질문도 접수 이메일로 받습니다. 질문이 많이 겹치면 모아서 홈페이지 FAQ에 올리고, 개별 질문은 메일로 답합니다.

## 마무리: 기억할 4가지

1. **11/15까지 접수:** 기획서 + 참가자 전원 서명 동의서, 제출 메일에 전원 CC
2. **개발 산출물은 선택·가산점:** 2차 PT 대상팀은 PT 전까지 앱 개발 완료
3. **차량 특화 경험에 집중:** SDK·API를 핵심 기능과 사용자 경험에 연결
4. **온라인 서베이:** Playground를 써 본 경험에 대한 설문(QR). 다시보기와 함께 팝업으로 다시 올림. 좋은 피드백을 준 참가자 일부에게 선물

최신 안내와 단계별 결과는 공식 홈페이지 공지사항에서 확인합니다.
